# Moosiac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Moosiac, a browser-based AI-assisted sheet-music composition app (notation editor + MIDI sequencer + mock AI generation) as a complete, tested, runnable TypeScript application.

**Architecture:** A canonical, immutable, tick-based (480 PPQ) score model is the single source of truth. All mutations flow through undoable commands. UI (React + MUI), rendering (VexFlow SVG), playback (Tone.js), file formats (MIDI/MusicXML), persistence (Dexie), and AI generation (provider abstraction with a deterministic seeded mock) are adapters around the pure domain layer.

**Tech Stack:** React 18, TypeScript (strict), Vite, Material UI, Zustand + Immer, Zod, VexFlow 4, Tone.js, @tonejs/midi, Dexie, Vitest, React Testing Library, Playwright, ESLint (flat config), Prettier.

**The authoritative requirements document is `docs/spec.md` in this repo.** Every task below cites the spec sections it implements; the spec text governs details the plan doesn't repeat. Read the cited sections before implementing.

## Global Constraints

- Package name `scoresmith`. All commands must work via npm: `npm install`, `npm run dev`, `npm run build`, `npm run preview`, `npm run lint`, `npm run typecheck`, `npm run test`, `npm run test:e2e` (spec §35).
- TypeScript `strict: true`; the build must have zero TS errors; no critical lint errors (spec §35).
- Default PPQ = 480, configurable per score (spec §4).
- Never use floating-point seconds as the musical timeline; positions/durations are integer ticks (spec §4, §37.6).
- Domain code (`src/domain/**`) must not import React, MUI, VexFlow, Tone.js, @tonejs/midi, Dexie, or browser-only APIs (spec §3, §37.14). `crypto.randomUUID` is allowed via the injected/fallback helper in `src/domain/score/ids.ts`.
- Every score mutation goes through a `ScoreCommand` (spec §37.7). No direct store writes to the score outside the command manager.
- VexFlow objects and Tone.js objects must never be stored in Zustand state (spec §37.2–3).
- All AI generation responses are Zod-validated and structurally validated before use (spec §37.8).
- Regeneration previews are non-destructive; acceptance is a single undoable command (spec §37.9–10).
- Selection is centralized in one store slice shared by all views (spec §37.13).
- Core features must work offline via the deterministic seeded mock provider (spec §37.15).
- MVP scope boundaries per spec §38 — do not implement listed "future work" items; note them in docs.
- File layout per spec §5. Prefer small focused modules; avoid monolithic files.
- Commit style: conventional commits (`feat:`, `test:`, `fix:`, `docs:`, `chore:`), commit after each green test cycle.

### Task 4: Domain — validation, quantization, voice allocation

**Spec:** §23, §24, §25. **Files:** Create `src/domain/validation/validator.ts`, `src/domain/validation/issues.ts` (codes as const object), `src/domain/quantization/quantize.ts`, `src/domain/quantization/options.ts`, `src/domain/voicing/allocate.ts` (+ tests).

- `validateScore(score): ValidationIssue[]` covering every rule in spec §23 (unique IDs; pitch ranges; positive durations; nonnegative ticks; velocity 0–127; program 0–127; channel 0–15; time signature numerator ≥1 & denominator in {1,2,4,8,16,32}; key fifths -7..7; measure voice content sums to measure duration (error if overfull, warning if underfull); events within their measure; tie targets exist (tieStart has a matching tieStop note at the next position with same pitch — warning otherwise); trackId/voiceId references valid; overlapping same-pitch events in a voice (error); >N simultaneous notes warning; tempo map sorted & bpm 20–400; measure index/startTick ordering consistent).
- `quantize.ts`: `quantizeEvents(events: MusicalEvent[], opts: QuantizeOptions): MusicalEvent[]` with `QuantizeOptions = { grid: number /* ticks */; quantizeStarts: boolean; quantizeDurations: boolean; swing?: number /* 0..1 */; tripletGrid?: boolean; minDurationTicks?: number; humanizeToleranceTicks?: number; chordToleranceTicks?: number; legatoCleanup?: boolean; resolveOverlaps?: boolean; fillGaps?: boolean }`. Behaviors per spec §24: snap starts to nearest grid (or triplet grid), swing shifts every second grid slot, group near-simultaneous onsets into chords (same start), drop notes shorter than min duration, trim overlapping same-voice notes (resolveOverlaps), extend to next note start (legatoCleanup), fill gaps with rests where requested. Pure function; extensive edge-case tests (note at exact midpoint, zero-length after quantize → min duration, swing at 0/0.5, chord grouping tolerance).
- `allocate.ts`: `allocateVoices(notes: NoteEvent[], opts: { maxVoices: number; splitPoint?: number /* midi, for grand-staff assignment */ }): Array<{ voiceIndex: number; staff: "upper" | "lower"; notes: NoteEvent[] }>` — group simultaneous equal-duration notes as chords in one voice; overlapping independent lines go to separate voices preferring minimal voice-hopping (assign to the voice whose last note ended closest before the new note); notes below splitPoint (default 60) go to lower staff for grand-staff tracks.
