# S3M Decoder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import Scream Tracker 3 `.s3m` modules — the first format whose packing, addressing and effect lettering are all genuinely unlike MOD's.

**Architecture:** A parapointer-addressed reader: fixed header, then order list, instrument and pattern pointer tables, each pointer multiplied by 16 to give a file offset. Its own effect normaliser, because S3M numbers commands 1=A…26=Z where MOD uses nibbles. Sample data is reached only to be skipped. No change to `TrackerModule` or `trackerToScore`.

**Tech Stack:** TypeScript (strict, ESM, extensionless relative imports built by `tsc`), Vitest.

## Global Constraints

- **Repos:** `music_io` for everything except the final app copy change and docs. `music_types` and `music_lib` are **not** touched.
- **Relative imports carry a `.js` extension** even from `.ts` files. House style; do not "fix" it.
- **Cross-repo propagation:** after changing `music_io` run `bun run clean && bun run build`, `rsync -a --delete dist/ ../<consumer>/node_modules/@sudobility/music_io/dist/` for both `music_lib` and `music_app`, then `rm -rf ../music_app/node_modules/.vite`.
- **`music_io` does bytes, `music_lib` does music.** The reader returns a `TrackerModule` and stops.
- **Sample payloads are skipped, never decoded.** S3M addresses them by parapointer from the instrument header; the reader never follows those pointers.
- **Verify by sabotage.** After each task's tests pass, break the implementation line the test targets, confirm that test fails, restore.
- **Spec:** `docs/superpowers/specs/2026-08-17-tracker-formats-design.md`.
- **Do not commit manually.** When the plan says deploy, run `music_app/scripts/push_all.sh`.

## Format facts, verified against two real files

Measured against `rhythm.s3m` (modarchive 69391, "S3M --> moving that rhythm") and `s3m.s3m` (modarchive 54606, "Portal to hell"). **Two real-world quirks below would each break a decoder written from the specification alone**, which is why both files are used rather than one.

**Header, 96 bytes:**

| Offset | Type      | Field                   | rhythm.s3m                   |
| ------ | --------- | ----------------------- | ---------------------------- |
| 0      | char[28]  | title                   | `S3M --> moving that rhythm` |
| 28     | uint8     | 0x1A end-of-text marker | 0x1A                         |
| 29     | uint8     | type (0x10 = module)    | 0x10                         |
| 32     | uint16    | ordNum                  | 28                           |
| 34     | uint16    | insNum                  | 26                           |
| 36     | uint16    | patNum                  | 9                            |
| 38     | uint16    | flags                   | 0                            |
| 40     | uint16    | trackerVersion          | 0x1320                       |
| 42     | uint16    | sampleType              | 2                            |
| 44     | char[4]   | **`SCRM`**              | `SCRM`                       |
| 48     | uint8     | globalVolume            | 64                           |
| 49     | uint8     | initialSpeed            | 2                            |
| 50     | uint8     | initialTempo            | 125                          |
| 51     | uint8     | masterVolume            | 176                          |
| 53     | uint8     | defaultPan flag         | 0xFC                         |
| 64     | uint8[32] | channelSettings         | `[0,8,1,9,2,10,…]`           |

Then, in order: `orders[ordNum]` bytes at 96; `uint16[insNum]` instrument parapointers; `uint16[patNum]` pattern parapointers. **A parapointer times 16 is a file offset.**

**Instrument, 80 bytes at `para * 16`:**

| Offset | Type     | Field                               |
| ------ | -------- | ----------------------------------- |
| 0      | uint8    | type — 1 sample, 0 empty, 2–7 AdLib |
| 16     | uint32   | length                              |
| 48     | char[28] | name                                |
| 76     | char[4]  | `SCRS`                              |

Verified: names read `Inesyn1`, `Inedrum1`, `AngryTechnoNoise`, `holic1`, `808clap.snd`. **Instrument 5 of `rhythm.s3m` has `type = 0` and no `SCRS` magic** — an empty slot, which the reader must accept rather than reject.

**Pattern at `para * 16`:** uint16 LE self-length at 0, packed events from +2. Per event:

- Read a flag byte. **Zero ends the row.**
- `flag & 31` is the channel.
- `flag & 32` → a note byte **and** an instrument byte follow (two bytes, always together).
- `flag & 64` → a volume byte follows.
- `flag & 128` → a command byte **and** an info byte follow.

**Note byte is `(octave << 4) | note`,** not a linear number. `0xFF` is empty and `0xFE` is a note cut. Verified across both files: every note nibble is ≤ 11, which is what that packing implies and what a wrong unpacking would break first. MIDI is `12 + octave * 12 + note`, giving 53–79 for one file and 37–84 for the other — both sane registers.

**Commands are numbered 1=A … 26=Z**, unlike MOD's nibbles. The three that matter: **1 (A) sets speed, 20 (T) sets tempo, 3 (C) breaks the pattern.** Observed commands across both files: 1, 2, 4, 5, 6.

### Quirk 1: patterns end early and the declared length lies

`rhythm.s3m` unpacks perfectly — all 9 patterns, exactly 64 rows, consuming exactly the declared bytes. **`s3m.s3m` does not.** Every one of its 31 patterns yields 62 or 63 rows, and 24 of them consume exactly one byte _more_ than declared:

```
pattern 3:  rows=63 consumed=725 declared=724
pattern 27: rows=62 consumed=64  declared=64
```

This is not a desynchronised unpacker — if it were, note nibbles would exceed 11 and pitches would be nonsense, and neither happens. The writer simply omits trailing empty rows, and sometimes the final row terminator.

**So the reader must not trust the declared length to terminate, and must not require 64 rows of data.** It reads events until it has 64 rows or the data runs out, pads any remaining rows as empty, and clamps every read to the buffer. A decoder that asserted "64 rows, exactly the declared bytes" would reject a real, widely-downloaded module.

### Quirk 2: the header declares more channels than the patterns use

`rhythm.s3m` marks 16 channels enabled in `channelSettings` but its patterns only ever reference channels 0–8. Sizing rows from the header alone leaves seven permanently empty columns; sizing from usage alone would drop notes on a file whose patterns reach past what the header declares.

**So the width is `max(enabled channel count, highest channel index used + 1)`, capped at 32.** Empty columns downstream are harmless — `trackerToScore` groups by instrument and creates tracks only for instruments actually played — so erring wide costs nothing and erring narrow loses music.

```ts
/**
 * Scream Tracker 3 commands, reduced to what notation import uses.
 *
 * S3M numbers its commands 1=A through 26=Z, where MOD packs an effect into a
 * nibble — so this cannot share MOD's normaliser, and sharing it behind a
 * format flag would put back exactly the branching the neutral cell exists to
 * remove.
 *
 * The split is also cleaner than MOD's: `A` sets ticks per row and `T` sets
 * BPM, where MOD's single `F` means one or the other depending on whether the
 * parameter clears 0x20.
 *
 * `B` (position jump) is deliberately ignored, as it is for MOD: honouring it
 * can loop forever and a score has no way to express it.
 */
import type { TrackerCell } from '@sudobility/music_types';

/** A = 1: ticks per row. */
const SET_SPEED = 1;
/** C = 3: end this pattern here. */
const PATTERN_BREAK = 3;
/** T = 20: beats per minute. */
const SET_TEMPO = 20;

export function applyS3mEffect(cell: TrackerCell, command: number, info: number): void {
  if (command === SET_SPEED) {
    if (info > 0) cell.speed = info;
    return;
  }
  if (command === SET_TEMPO) {
    if (info > 0) cell.bpm = info;
    return;
  }
  if (command === PATTERN_BREAK) cell.patternBreak = true;
}
```

- [ ] **Step 1: Write it**

```ts
/**
 * A hand-built S3M file, for testing the reader against known bytes.
 *
 * Parapointers make this fiddlier than the other fixtures: the header holds
 * offsets to the instrument and pattern blocks divided by sixteen, so the
 * builder has to lay the file out and then go back and fill them in. Every
 * block is padded to a 16-byte boundary for that reason.
 *
 * Offsets mirror those measured from two real modules; the acceptance test
 * against those files is what stops this and the reader agreeing with each
 * other while both being wrong.
 */

export type S3mCellSpec = {
  channel: number;
  /** A MIDI-ish `(octave << 4) | note`, or 255 for empty, 254 for a cut. */
  note?: number;
  instrument?: number;
  volume?: number;
  command?: number;
  info?: number;
};

export type S3mOptions = {
  title?: string;
  /** How many entries of `channelSettings` are marked enabled. */
  channels?: number;
  instrumentNames?: string[];
  order?: number[];
  /** `patterns[p][row]` — a list of events for that row. */
  patterns?: S3mCellSpec[][][];
  initialSpeed?: number;
  initialTempo?: number;
  /** Drop the final row terminator, as a real writer does. See Quirk 1. */
  truncateLastRow?: boolean;
};

const PARA = 16;

function ascii(out: Uint8Array, at: number, text: string, length: number): void {
  for (let i = 0; i < length; i += 1) out[at + i] = i < text.length ? text.charCodeAt(i) : 0;
}

function packPattern(rows: S3mCellSpec[][], truncate: boolean): Uint8Array {
  const body: number[] = [];
  for (let row = 0; row < 64; row += 1) {
    for (const cell of rows[row] ?? []) {
      let flag = cell.channel & 31;
      if (cell.note !== undefined) flag |= 32;
      if (cell.volume !== undefined) flag |= 64;
      if (cell.command !== undefined) flag |= 128;
      body.push(flag);
      // Note and instrument travel together under one flag bit.
      if (cell.note !== undefined) body.push(cell.note, cell.instrument ?? 0);
      if (cell.volume !== undefined) body.push(cell.volume);
      if (cell.command !== undefined) body.push(cell.command, cell.info ?? 0);
    }
    const last = row === 63;
    if (!(last && truncate)) body.push(0);
  }
  const out = new Uint8Array(2 + body.length);
  new DataView(out.buffer).setUint16(0, out.length, true);
  out.set(body, 2);
  return out;
}

function instrumentChunk(name: string, empty: boolean): Uint8Array {
  const out = new Uint8Array(80);
  out[0] = empty ? 0 : 1;
  if (!empty) {
    new DataView(out.buffer).setUint32(16, 64, true); // a nominal sample length
    ascii(out, 48, name, 28);
    ascii(out, 76, 'SCRS', 4);
  }
  return out;
}

export function buildS3m(opts: S3mOptions = {}): ArrayBuffer {
  const channels = opts.channels ?? 4;
  const names = opts.instrumentNames ?? ['Lead'];
  const order = opts.order ?? [0];
  const patterns = opts.patterns ?? [[]];

  const packed = patterns.map((p) => packPattern(p, opts.truncateLastRow ?? false));
  const instruments = names.map((n) => instrumentChunk(n, n.length === 0));

  // Header, orders, then the two pointer tables — then everything padded to
  // 16-byte boundaries so a parapointer can address it.
  const tableAt = 96 + order.length;
  const bodyAt = Math.ceil((tableAt + instruments.length * 2 + packed.length * 2) / PARA) * PARA;

  const blocks: Array<{ data: Uint8Array; at: number }> = [];
  let at = bodyAt;
  for (const data of [...instruments, ...packed]) {
    blocks.push({ data, at });
    at = Math.ceil((at + data.length) / PARA) * PARA;
  }

  const out = new Uint8Array(at);
  const view = new DataView(out.buffer);
  ascii(out, 0, opts.title ?? 'Fixture', 28);
  out[28] = 0x1a;
  out[29] = 0x10;
  view.setUint16(32, order.length, true);
  view.setUint16(34, instruments.length, true);
  view.setUint16(36, packed.length, true);
  view.setUint16(42, 2, true);
  ascii(out, 44, 'SCRM', 4);
  out[48] = 64;
  out[49] = opts.initialSpeed ?? 6;
  out[50] = opts.initialTempo ?? 125;
  out[51] = 176;
  out[53] = 0xfc;
  // 255 marks a channel unused; anything below 16 is an enabled PCM channel.
  out.fill(255, 64, 96);
  for (let i = 0; i < channels; i += 1) out[64 + i] = i;

  order.forEach((value, i) => {
    out[96 + i] = value;
  });
  blocks.forEach(({ data, at: blockAt }, i) => {
    out.set(data, blockAt);
    view.setUint16(tableAt + i * 2, blockAt / PARA, true);
  });

  return out.buffer;
}
```

```ts
/**
 * Reading a Scream Tracker 3 module into the neutral tracker model.
 *
 * Unlike MOD and DSM, S3M is *parapointer-addressed*: the header carries
 * tables of 16-bit pointers which, multiplied by sixteen, give file offsets for
 * each instrument and pattern. Nothing is laid out in sequence, so nothing can
 * be read by walking forward.
 *
 * **Measured against two real modules** (modarchive 69391 and 54606), and two
 * of their behaviours contradict the specification — see `unpackPattern` and
 * `channelCount`. A reader written from the format documentation alone rejects
 * one of those files outright.
 *
 * Sample data is never read. Each instrument header carries its own parapointer
 * to the audio, and this reader simply never follows it.
 */
import type { TrackerCell, TrackerInstrument, TrackerModule } from '@sudobility/music_types';
import { applyS3mEffect } from './s3m-effects.js';

const HEADER_BYTES = 96;
const MAGIC_AT = 44;
const CHANNEL_SETTINGS_AT = 64;
const CHANNEL_SETTINGS_COUNT = 32;
const ORDERS_AT = 96;
/** A parapointer is a file offset divided by this. */
const PARA = 16;

const INSTRUMENT_NAME_AT = 48;
const INSTRUMENT_NAME_LENGTH = 28;

/** S3M patterns are 64 rows, though the data may stop short — see `unpackPattern`. */
const ROWS_PER_PATTERN = 64;
/** `(octave << 4) | note`, so C-0 is 0x00 and MIDI 12. */
const NOTE_BASE = 12;
const NOTE_EMPTY = 0xff;
const NOTE_CUT = 0xfe;

function ascii(bytes: Uint8Array, at: number, length: number): string {
  let out = '';
  for (let i = 0; i < length; i += 1) {
    const c = bytes[at + i];
    if (c === 0) break;
    if (c >= 32 && c < 127) out += String.fromCharCode(c);
  }
  return out.trim();
}

function fourCC(bytes: Uint8Array, at: number): string {
  if (at + 4 > bytes.length) return '';
  return String.fromCharCode(bytes[at], bytes[at + 1], bytes[at + 2], bytes[at + 3]);
}

export function readS3m(buffer: ArrayBuffer): TrackerModule {
  const bytes = new Uint8Array(buffer);
  if (bytes.length < HEADER_BYTES) {
    throw new Error('Not a Scream Tracker module: file is too short');
  }
  if (fourCC(bytes, MAGIC_AT) !== 'SCRM') {
    throw new Error(`Not a Scream Tracker module: signature is "${fourCC(bytes, MAGIC_AT)}"`);
  }

  const view = new DataView(bytes.buffer, bytes.byteOffset, bytes.byteLength);
  const ordNum = view.getUint16(32, true);
  const insNum = view.getUint16(34, true);
  const patNum = view.getUint16(36, true);

  const order: number[] = [];
  for (let i = 0; i < ordNum; i += 1) order.push(bytes[ORDERS_AT + i]);

  const tableAt = ORDERS_AT + ordNum;
  const instrumentParas: number[] = [];
  for (let i = 0; i < insNum; i += 1) instrumentParas.push(view.getUint16(tableAt + i * 2, true));
  const patternParas: number[] = [];
  for (let i = 0; i < patNum; i += 1) {
    patternParas.push(view.getUint16(tableAt + insNum * 2 + i * 2, true));
  }

  const instruments: TrackerInstrument[] = instrumentParas.map((para, i) => {
    const at = para * PARA;
    // An empty slot has type 0 and no SCRS magic — a real module has one, and
    // rejecting it would reject the module.
    const usable = para !== 0 && at + INSTRUMENT_NAME_AT + INSTRUMENT_NAME_LENGTH <= bytes.length;
    return {
      index: i + 1,
      name: usable ? ascii(bytes, at + INSTRUMENT_NAME_AT, INSTRUMENT_NAME_LENGTH) : '',
    };
  });

  const patterns: TrackerCell[][][] = [];

  return {
    format: 's3m',
    title: ascii(bytes, 0, 28),
    channels: 4,
    instruments,
    order,
    patterns,
  };
}
```

```ts
type RawEvent = { channel: number; apply: (cell: TrackerCell) => void };

/**
 * One packed pattern, as a list of events per row.
 *
 * Returned before the channel width is known, because the width depends on the
 * highest channel any pattern touches — see `channelCount`.
 *
 * **The declared length is not trusted to terminate the data, and 64 rows of
 * data are not required.** A real module (modarchive 54606) yields 62 or 63
 * rows for every one of its patterns, and 24 of them run one byte past their
 * declared length: the writer omits trailing empty rows and sometimes the final
 * terminator. Every read is clamped to the buffer and the remaining rows are
 * left empty.
 */
function unpackPattern(bytes: Uint8Array, para: number): RawEvent[][] {
  const rows: RawEvent[][] = [];
  if (para === 0) return rows;

  const start = para * PARA;
  if (start + 2 > bytes.length) return rows;
  const view = new DataView(bytes.buffer, bytes.byteOffset, bytes.byteLength);
  const declared = view.getUint16(start, true);
  const end = Math.min(start + declared, bytes.length);

  let at = start + 2;
  let row: RawEvent[] = [];
  while (rows.length < ROWS_PER_PATTERN && at < end) {
    const flag = bytes[at];
    at += 1;
    if (flag === 0) {
      rows.push(row);
      row = [];
      continue;
    }

    const channel = flag & 31;
    let note: number | 'off' | null | undefined;
    let instrument: number | undefined;
    let command: number | undefined;
    let info = 0;

    if (flag & 32) {
      // Note and instrument travel together under this one bit.
      const raw = bytes[at];
      instrument = bytes[at + 1];
      at += 2;
      if (raw === NOTE_EMPTY) note = null;
      else if (raw === NOTE_CUT) note = 'off';
      else note = NOTE_BASE + (raw >> 4) * 12 + (raw & 0x0f);
    }
    if (flag & 64) {
      // Read and discarded: a tracker volume column is a performance
      // instruction, and the score model has velocity for that at entry.
      at += 1;
    }
    if (flag & 128) {
      command = bytes[at];
      info = bytes[at + 1];
      at += 2;
    }
    row.push({
      channel,
      apply: (cell) => {
        if (note !== undefined) cell.note = note;
        if (instrument !== undefined) cell.instrument = instrument;
        if (command !== undefined) applyS3mEffect(cell, command, info);
      },
    });
  }
  // A row left part-built when the data ran out is still a row.
  if (row.length > 0 && rows.length < ROWS_PER_PATTERN) rows.push(row);
  return rows;
}

/**
 * How many columns each row needs.
 *
 * The wider of what the header enables and what the patterns actually reach.
 * A real module (modarchive 69391) marks sixteen channels enabled and uses
 * nine; another could reference a channel the header never enabled. Erring wide
 * costs empty columns, which are harmless because `trackerToScore` builds
 * tracks from instruments rather than channels. Erring narrow loses notes.
 */
function channelCount(bytes: Uint8Array, patterns: RawEvent[][][]): number {
  let enabled = 0;
  for (let i = 0; i < CHANNEL_SETTINGS_COUNT; i += 1) {
    const setting = bytes[CHANNEL_SETTINGS_AT + i];
    if (setting !== 0xff && (setting & 0x80) === 0) enabled += 1;
  }
  let highest = -1;
  for (const pattern of patterns) {
    for (const row of pattern) {
      for (const event of row) highest = Math.max(highest, event.channel);
    }
  }
  return Math.min(CHANNEL_SETTINGS_COUNT, Math.max(enabled, highest + 1, 1));
}
```

Then replace the placeholder in `readS3m`:

```ts

const patterns: TrackerCell[][][] = raw.map((pattern) => {
  const rows: TrackerCell[][] = [];
  for (let r = 0; r < ROWS_PER_PATTERN; r += 1) {
    const row: TrackerCell[] = Array.from({ length: channels }, () => ({
      instrument: 0,
      note: null,
    }));
    for (const event of pattern[r] ?? []) {
      if (event.channel < channels) event.apply(row[event.channel]);
    }
    rows.push(row);
  }
  return rows;
});
```
